# llm-wiki

A personal knowledge base assistant powered by [Claude Code](https://docs.anthropic.com/en/docs/claude-code) and [Obsidian](https://obsidian.md). It maintains your vault, generates daily morning briefings, runs weekly reviews, and collects personal data from health, music, and podcast sources — all automatically via systemd timers.

The core idea: teach Claude your world through a `CLAUDE.md` file, then let it work for you on a schedule. The system grows over time as you add data sources and operations.

## What It Does

- **Daily briefings** — A morning summary with calendar, todos, health stats, music listening, podcast highlights, and backlog surfacing
- **Weekly reviews** — Synthesize the week's accomplishments, carry forward incomplete items, track project status
- **Vault maintenance** — Health checks for orphaned pages, broken links, missing frontmatter
- **Data collection** — Apple Health metrics, Apple Music listening history, Pocket Casts episodes, Last.fm scrobbles
- **Session memory** — Each run remembers context from the last, providing continuity across days
- **Engagement-aware backlog rotation** — Surfaces books, games, blog ideas, and projects on a rotating schedule, tracking whether you actually engage with suggestions

## Architecture

```
                    systemd timers (schedule)
                          |
                    run-jarvis.sh / run-collector.sh
                          |
              +-----------+-----------+
              |                       |
        claude -p "prompt"      Python collectors
        (Claude Code headless)   (Apple Health, Music, Podcasts)
              |                       |
              v                       v
        Obsidian vault           SQLite database
        (_llm/ directory)        (_llm/data/jarvis.db)
              |
        MCP integrations
        (Google Calendar, Gmail)
```

Claude Code runs in headless mode (`claude -p`), reading `CLAUDE.md` and `vault-config.md` to understand your vault. It generates markdown files, queries the SQLite database, and uses MCP integrations for live data.

## Prerequisites

- **Linux with systemd** (user units)
- **Python 3.13+**
- **[Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code)** (`claude`)
- **[Obsidian](https://obsidian.md)** with a vault
- **Obsidian CLI** (optional, for vault queries) — install via Obsidian community plugins

Optional data sources (enable the ones you use):
- Apple Health via [Health Auto Export](https://apps.apple.com/app/health-auto-export/id1115567461) iOS app
- Apple Music developer account (MusicKit API)
- Last.fm account (alternative to Apple Music)
- Pocket Casts account

## Quick Start

```bash
# 1. Clone
git clone https://github.com/YOUR_USERNAME/llm-wiki.git
cd llm-wiki

# 2. Run interactive setup
bash setup.sh

# 3. Customize your vault configuration
#    Edit vault-config.md to map YOUR vault's folder structure,
#    tags, key files, and backlog rotation schedule.

# 4. Fill in API credentials (for data collectors you want to use)
#    Edit ~/.config/jarvis/credentials.env

# 5. Enable systemd timers
systemctl --user daemon-reload
systemctl --user enable --now jarvis-daily.timer

# 6. Test with a manual run
./scripts/run-jarvis.sh daily-briefing
```

## How It Works

### The CLAUDE.md System

`CLAUDE.md` is the brain — a ~350-line instruction file that teaches Claude Code:
- **Core rules**: never delete user content, machine output goes in `_llm/` only
- **Operations**: how to run daily briefings, weekly reviews, vault health checks
- **Data integrations**: how to query the SQLite database for health, music, and podcast data
- **Session memory**: how to maintain context across runs

`vault-config.md` (gitignored, generated by `setup.sh`) holds your personal vault structure — folder layout, tags, key files, and backlog rotation schedule. Together, these two files give Claude a complete picture of your knowledge base.

### Data Collection

Python scripts collect personal data on systemd timers and store it in a single SQLite database (`_llm/data/jarvis.db`). Claude queries this database during briefing generation via `query_db.py`.

| Collector | Source | Schedule |
|-----------|--------|----------|
| `health-receiver.py` | Apple Health Auto Export (webhook) | Always-on |
| `collect-apple-music.py` | Apple Music API | Every 6 hours |
| `collect-lastfm.py` | Last.fm API | Periodic |
| `collect-pocketcasts.py` | Pocket Casts API | Daily at 06:00 |

### Scheduled Operations

| Timer | Operation | What It Does |
|-------|-----------|-------------|
| `jarvis-daily.timer` | Daily briefing | Morning summary with all sections |
| `jarvis-weekly-review.timer` | Weekly review | Week synthesis, todo carry-forward |
| `jarvis-lint.timer` | Vault health check | Orphans, broken links, stale tasks |
| `jarvis-project-status.timer` | Project dashboard | Status across all projects |

### MCP Integrations

If you use Claude Code with Google Calendar and Gmail MCP servers, the daily briefing will include:
- Today's and tomorrow's calendar events
- Unread email count and important messages

These are optional — the briefing works without them, just with less data.

## Customization

### Adding a Data Source

1. Write a Python collector script in `scripts/` (see existing ones for patterns)
2. Use `db.py` for database access — add new tables to `SCHEMA_SQL` if needed
3. Add a `query_db.py` subcommand to expose the data to Claude
4. Create a systemd service + timer in `systemd/` (copy a `.service.template`)
5. Add the new data section to the daily briefing template in `CLAUDE.md`

### Changing Vault Structure

Edit `vault-config.md` — this is where all your personal vault details live. CLAUDE.md references it for folder structure, tags, key files, and backlog rotation.

### Modifying Operations

Operations are defined in `CLAUDE.md` (the generic framework) and executed via prompt files in `prompts/`. To modify an operation, edit the relevant prompt file. To add a new operation, create a new prompt and a corresponding systemd timer.

### Adding a New Operation

1. Write a prompt in `prompts/my-operation.md`
2. Test it: `./scripts/run-jarvis.sh my-operation`
3. Create `systemd/jarvis-my-operation.service.template` and `.timer`
4. Run `bash systemd/install.sh` to install

├── credentials.env.example      # Credentials template
